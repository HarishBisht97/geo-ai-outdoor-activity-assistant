# API

Base path `/api/v1`. OpenAPI: `GET /openapi.json`, UI at `/docs`. Frontend types: `frontend/src/types/api.ts` generated by `pnpm gen:types` from `frontend/openapi.json`.

## `POST /api/v1/recommend`

Body:

```json
{
  "question": "Where can I go running tomorrow morning near Powai?",
  "preferences": {
    "radius_km": 10,
    "travel_mode": "walking",
    "origin": { "lat": 19.12, "lon": 72.91, "label": "Your location" },
    "sensitivities": ["respiratory"]
  },
  "overrides": { "activity": "running", "location_text": "Powai" }
}
```

`overrides` are structured answers from the clarification UI; they win over extraction.

Response (abridged): `status` (`ok` | `needs_clarification` | `no_suitable_option` | `insufficient_data`), `interpretation`, `recommendations[]` (venue, best slot, score components, conditions as `EvidenceValue`, travel, context, positives/negatives), `candidates_considered[]`, `timeline` (heatmap + hourly series), `facts[]`, `narrative`, `warnings[]`, `sources[]`, `attribution[]`, `disclaimer`, `timings_ms`, `data_mode`.

## `POST /api/v1/recommend/stream`

Same body. `text/event-stream`:

1. `stage` `{stage, detail}` — understanding, locating, finding_places, fetching_conditions, ranking, explaining.
2. `ranking` — full `RecommendResponse` without waiting for the narrative.
3. `done` — full response including `narrative`.
4. `error` `{code, message, request_id}`.

EventSource cannot POST, so the UI uses `fetch` and `parseSse`.

## Errors

```json
{ "error": { "code": "validation_error", "message": "The request is invalid.", "request_id": "…", "details": {} } }
```

`429 rate_limited` includes `Retry-After`. `X-Request-ID` is echoed (or generated if missing/unsafe).

## Health

`GET /health` → `{status, uptime_s, version}`. `GET /ready` → model loaded, last-seen provider status. Ready **never** calls external APIs. HTTP 503 only while the model is expected and not yet loaded; the API still serves via the keyword parser.
